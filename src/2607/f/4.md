## Устройство и принцип работы процессоров
<!--

Компьютер — это устройство, которое механически обрабатывает данные. Здесь «механически» означает, что его принципы просты и легко понятны. Центральный процессор (CPU), выступающий в роли мозга компьютера, — тоже такое устройство.

### Instructions and Their Encoding

### Инструкции и их кодирование
<!--
You should all be familiar with electronic calculators. Modern calculators can perform at least the four arithmetic operations of addition, subtraction, multiplication, and division. The functionality of a processor far exceeds that of an electronic calculator. As a device for processing data, its processing methods are certainly not limited to a single approach. Additionally, since a processor is a device that mechanically processes data, the type of processing it performs should be controlled by some means, and it does not possess the ability to think independently. The medium for controlling the processor is instructions. For example, we can use an addition instruction to control the processor to add two pieces of data together.This is very similar to entering `1+2=` on an electronic calculator to control it.
-->
Вам всем наверняка знакомы электронные калькуляторы. Современные калькуляторы умеют выполнять как минимум четыре арифметических действия: сложение, вычитание, умножение и деление. Возможности процессора намного превосходят возможности электронного калькулятора. Как устройство для обработки данных, он, разумеется, не ограничен единственным способом обработки. Кроме того, поскольку процессор — это устройство, механически обрабатывающее данные, то, какую именно обработку он выполняет, должно каким-то образом управляться извне, ведь он не обладает способностью мыслить самостоятельно. Средством управления процессором служат инструкции. Например, с помощью инструкции сложения можно заставить процессор сложить два фрагмента данных. Это очень похоже на ввод `1+2=` на электронном калькуляторе, чтобы им управлять.

<!--
To 'use an addition instruction to control the processor to add two pieces of data', it means that an instruction needs to provide two types of information: On one hand, there are many types of data that a computer needs to process, so the instruction must specify which data to process, which is referred to as the 'operand' field of the instruction; On the other hand, there are also many ways for a computer to process data, so the instruction must also specify the method of data processing, which is referred to as the 'opcode' field of the instruction.
-->
Фраза «с помощью инструкции сложения заставить процессор сложить два фрагмента данных» означает, что инструкция должна предоставлять два вида информации: с одной стороны, компьютеру приходится обрабатывать данные многих видов, поэтому инструкция должна указывать, какие именно данные обрабатывать, — это называется полем «операнд» инструкции; с другой стороны, у компьютера также есть много способов обработки данных, поэтому инструкция должна также указывать способ обработки данных, — это называется полем «код операции» инструкции.

<!--
```text
+---------+---------+
| opcode  | operand |
+---------+---------+
```
-->
```text
+--------------+---------+
| код операции | операнд |
+--------------+---------+
```

> #### hint::«Процессор» в повседневной жизни: кухня
> На самом деле у многих понятий внутри процессора есть похожие аналоги в повседневной жизни. Например, кухня — это место для обработки ингредиентов. Повар обрабатывает ингредиенты по рецепту, в итоге получая различные блюда.
>
> То, как работает процессор, очень похоже на то, что происходит на кухне. Например, инструкция подобна пункту меню. То, что повар готовит по меню, можно понимать так, будто меню «управляет» действиями повара. В меню тоже есть понятия, похожие на «операнды» и «коды операций». Например, «помидор» и «яйцо» в блюде «жареные помидоры с яйцом» похожи на «операнды» — они указывают, что для блюда нужно обработать именно эти два ингредиента; а «обжарить» похоже на «код операции» — оно указывает тип кулинарной операции, которую нужно выполнить над ингредиентами. Блюда из меню, такие как дважды приготовленная свинина или рыба на пару, тоже можно понимать с точки зрения инструкций.

<!--
Some intermediate results need to be saved for later use, so a processor needs components that can store data. These components are called registers. A processor usually contains multiple registers organized into a register set, which some textbooks also call a register file. Because these registers are used to hold general-purpose data, they are called general-purpose registers (GPRs). Other registers serve specialized purposes and therefore do not belong to the GPRs.
-->
Некоторые промежуточные результаты нужно сохранять для дальнейшего использования, поэтому процессору нужны компоненты, способные хранить данные. Такие компоненты называются регистрами. Процессор обычно содержит несколько регистров, объединённых в набор регистров, который в некоторых учебниках также называют регистровым файлом. Поскольку эти регистры используются для хранения данных общего назначения, их называют регистрами общего назначения (GPR). Другие регистры служат для специализированных целей и поэтому не относятся к GPR.

<!--
For example, consider calculating `1+2+...+10`. Since a single addition instruction can add only two data values, the result of `1+2` must first be stored in some register `r` in the GPRs. The processor can then compute `r+3`, and so on. Therefore, the operand field of an instruction needs to specify which GPRs provide the input data and which GPR receives the result. For the opcode, the processor only needs a convention that defines which operation each opcode represents.
-->
Например, рассмотрим вычисление `1+2+...+10`. Поскольку одна инструкция сложения может сложить только два значения данных, результат `1+2` сначала нужно сохранить в каком-нибудь регистре `r` среди GPR. Затем процессор может вычислить `r+3`, и так далее. Поэтому поле операнда инструкции должно указывать, какие GPR предоставляют входные данные и какой GPR получает результат. Что касается кода операции, процессору достаточно соглашения, определяющего, какую операцию представляет каждый код операции.

<!--
> #### hint::The "Processor" in Daily Life: The Kitchen (2)
> The dish "twice-cooked pork" requires boiling prior to stir-frying. Therefore, the boiled meat must be temporarily placed into a bowl before being transferred back into the wok for stir-frying. The registers within a processor are analogous to the bowls in a kitchen, serving as temporary storage for ingredients during processing.
-->
> #### hint::«Процессор» в повседневной жизни: кухня (2)
> Для блюда «дважды приготовленная свинина» перед обжаркой мясо нужно отварить. Поэтому отваренное мясо нужно временно переложить в миску, прежде чем вернуть его обратно в вок для обжарки. Регистры внутри процессора аналогичны мискам на кухне — они служат временным хранилищем для ингредиентов в процессе обработки.

<!--
As a digital circuit, the processor can represent all information using `0` and `1`, and instructions are no exception. For example, a simple processor with 4 GPRs supports 3 types of instructions, two of which are as follows:
-->
Будучи цифровой схемой, процессор способен представлять всю информацию с помощью `0` и `1`, и инструкции не исключение. Например, простой процессор с 4 GPR поддерживает 3 типа инструкций, два из которых показаны ниже:

<!--
```text
 7  6 5  4 3   2 1   0
+----+----+-----+-----+
| 00 | rd | rs1 | rs2 | R[rd]=R[rs1]+R[rs2]    add instruction, add two registers together
+----+----+-----+-----+
| 10 | rd |    imm    | R[rd]=imm              li instruction, load immediate value, fill high bits with zeros
+----+----+-----+-----+
```
-->
```text
 7  6 5  4 3   2 1   0
+----+----+-----+-----+
| 00 | rd | rs1 | rs2 | R[rd]=R[rs1]+R[rs2]    инструкция add, складывает два регистра
+----+----+-----+-----+
| 10 | rd |    imm    | R[rd]=imm              инструкция li, загружает непосредственное значение, старшие биты заполняются нулями
+----+----+-----+-----+
```

<!--
Since there are only three types of instructions, a 2-bit opcode is sufficient to distinguish between all instructions. In the above example, the opcode is `00`, which represents the `add` instruction; the opcode is `10`, which represents the `li` instruction. For convenience, instructions usually have corresponding names, such as the add instruction and the `li` instruction.
-->
Поскольку типов инструкций всего три, для различения всех инструкций достаточно 2-битного кода операции. В приведённом выше примере код операции `00` представляет инструкцию `add`; код операции `10` представляет инструкцию `li`. Для удобства у инструкций обычно есть соответствующие названия, например инструкция add и инструкция `li`.

<!--
Regarding operands, since there are only 4 GPRs, a 2-bit number can be used to specify the address of a GPR (`00`, `01`, `10`, `11`). The source of the operand data is called the 'source register.' The above `add` instruction requires two source registers to obtain the addends, with the addresses of the two source registers denoted as `rs1` and `rs2`, respectively, and the contents stored in the GPRs represented as `R[rs1]` and `R[rs2]`; The destination where the operation is written is called the 'destination register', generally denoted as `rd`. Among these, the second `li` instruction has a slightly different operand format. Its source operand is no longer a GPR, but is directly parsed from the `imm` field in the instruction into a binary number for use. This type of operand is called an 'immediate operand'.
-->
Что касается операндов, поскольку GPR всего 4, для указания адреса GPR достаточно 2-битного числа (`00`, `01`, `10`, `11`). Источник данных операнда называется «регистром-источником». Приведённая выше инструкция `add` требует два регистра-источника, чтобы получить слагаемые; адреса этих двух регистров-источников обозначаются как `rs1` и `rs2` соответственно, а содержимое, хранящееся в GPR, обозначается как `R[rs1]` и `R[rs2]`; место, куда записывается результат операции, называется «регистром-приёмником» и обычно обозначается как `rd`. Среди них у второй инструкции, `li`, формат операнда немного отличается. Её исходный операнд — уже не GPR, а число, разбираемое напрямую из поля `imm` инструкции как двоичное значение. Такой тип операнда называется «непосредственным операндом».

<!--
In summary, the length of the above instructions is 8 bits. We can understand the meaning of an instruction based on the above instruction encoding rules. Some specific instruction examples are as follows:
-->
Таким образом, длина приведённых выше инструкций составляет 8 бит. Опираясь на приведённые выше правила кодирования инструкций, можно понять смысл инструкции. Ниже приведены несколько конкретных примеров инструкций:

<!--
```text
00100001   add instruction, add R[0] and R[1], and write the result to R[2]
10110000   li instruction, write the immediate value 0000 to R[3]
10000101   li instruction, write the immediate value 0101 to R[0]
```
-->
```text
00100001   инструкция add, складывает R[0] и R[1] и записывает результат в R[2]
10110000   инструкция li, записывает непосредственное значение 0000 в R[3]
10000101   инструкция li, записывает непосредственное значение 0101 в R[0]
```

### Stored-Program
-->
### Хранимая программа
<!--
In fact, computers, which we believe to be almost omnipotent, complete various complex tasks by continuously executing a series of instructions. The various software programs you run on your computer are ultimately executing a series of instructions. Therefore, the essence of a program is a sequence of instructions. You may find it hard to believe, because the above instructions are very simple and no different from those of an electronic calculator. So why are computers so much more powerful than electronic calculators?
-->
На самом деле компьютеры, которые мы считаем почти всемогущими, выполняют разнообразные сложные задачи, непрерывно исполняя последовательность инструкций. Различные программы, которые вы запускаете на своём компьютере, в конечном счёте тоже исполняют последовательность инструкций. Поэтому суть программы — это последовательность инструкций. Вам может быть трудно в это поверить, ведь рассмотренные выше инструкции очень просты и ничем не отличаются от инструкций электронного калькулятора. Так почему же компьютеры настолько мощнее электронных калькуляторов?

<!--
The answer lies in how computers work: they allow programs to automatically control the computer's execution. Specifically, we can first store a sequence of instructions in memory (such as the RAM of modern computers), and have the computer fetch instructions from memory to execute; crucially, after the computer completes executing one instruction, it proceeds to execute the next instruction. To enable the computer to know where the next instruction is located, there must also be a component that indicates which instruction is currently being executed, this component is called the 'Program Counter' (PC).
From now on, computers only need to do one thing:
-->
Ответ кроется в том, как работают компьютеры: они позволяют программе автоматически управлять выполнением компьютера. А именно, мы можем сначала сохранить последовательность инструкций в памяти (такой как RAM (оперативная память) современных компьютеров) и заставить компьютер извлекать инструкции из памяти для выполнения; что особенно важно, после того как компьютер завершает выполнение одной инструкции, он переходит к выполнению следующей инструкции. Чтобы компьютер знал, где находится следующая инструкция, также нужен компонент, указывающий, какая инструкция выполняется в данный момент, — этот компонент называется «счётчиком команд» (Program Counter, PC).
Теперь компьютеру нужно делать только одно:

<!--
```text
Repeat the following steps:
  Fetch the instruction from the memory location indicated by the PC.
  Execute the instruction.
  Update the PC.
```
-->
```text
Повторяйте следующие шаги:
  Извлеките инструкцию из ячейки памяти, на которую указывает PC.
  Выполните инструкцию.
  Обновите PC.
```

<!--
In this way, we only need to place a sequence of instructions in the memory, then let the PC point to the first instruction, and the computer will automatically execute this sequence of instructions without stopping. This is the basic idea of 'Stored-Program' computers. Today's mainstream computers are essentially all 'Stored-Program' computers.
-->
Таким образом, нам достаточно разместить последовательность инструкций в памяти, затем направить PC на первую инструкцию, и компьютер автоматически, без остановки, выполнит эту последовательность инструкций. В этом заключается основная идея компьютеров «с хранимой программой». По сути, все современные распространённые компьютеры — это компьютеры «с хранимой программой».

<!--
There is an even more ingenious design! Since the PC stores the location of the currently executing instruction, the PC should also be a register. In this case, we can also design corresponding instructions to modify it, thereby increasing the flexibility of the program execution process. For example, we can add a third instruction based on the two instructions mentioned above:
-->
Есть решение ещё более изящное! Поскольку PC хранит адрес выполняемой в данный момент инструкции, PC тоже должен быть регистром. В этом случае мы также можем спроектировать соответствующие инструкции для его изменения, тем самым повышая гибкость процесса выполнения программы. Например, мы можем добавить третью инструкцию к двум упомянутым выше:

<!--
```text
 7  6 5         2 1  0
+----+---- -----+-----+
| 11 |   addr   | rs2 | if (R[0]!=R[rs2]) PC=addr bner0 instruction, if not equal to R[0], jump
+----+----------+-----+
```
-->
```text
 7  6 5         2 1  0
+----+---- -----+-----+
| 11 |   addr   | rs2 | if (R[0]!=R[rs2]) PC=addr инструкция bner0, переход, если не равно R[0]
+----+----------+-----+
```

<!--
The `bner0` instruction is quite special; it stands for `Branch if Not Equal r0`. If `R[rs2]` and `R[0]` are not equal when this instruction is executed, the PC register is updated to `addr`, meaning that the PC points to the instruction at `addr`. However, the PC register is not used to process general data, so it does not belong to the GPR.
-->
Инструкция `bner0` довольно особая: она означает `Branch if Not Equal r0` («переход, если не равно r0»). Если при выполнении этой инструкции `R[rs2]` и `R[0]` не равны, регистр PC обновляется значением `addr`, то есть PC начинает указывать на инструкцию по адресу `addr`. Однако регистр PC не используется для обработки данных общего назначения, поэтому он не относится к GPR.

<!--
With these instructions, we can now have the computer perform some more complex tasks.
-->
С этими инструкциями теперь можно заставить компьютер выполнять более сложные задачи.

### An Example of Summing a Sequence of Numbers

### Пример суммирования последовательности чисел
<!--
Let's use instructions to calculate the sum of the sequence `1+2+...+10`. For ease of understanding, we will not use `0` and `1` to represent instructions. We will use `r0`, `r1`, `r2`, and `r3` to represent the four GPRs, and use commas to separate the operands of the instructions. Assume the following instruction sequence is stored in memory to calculate the sum of the above sequence, where the number before `:` represents the program counter (PC), and the text following `#` represents a comment:
-->
Вычислим с помощью инструкций сумму последовательности `1+2+...+10`. Для простоты понимания мы не будем представлять инструкции с помощью `0` и `1`. Мы будем использовать `r0`, `r1`, `r2` и `r3` для обозначения четырёх GPR, а операнды инструкций будем разделять запятыми. Предположим, что в памяти хранится следующая последовательность инструкций для вычисления суммы указанной выше последовательности, где число перед `:` обозначает счётчик команд (PC), а текст после `#` обозначает комментарий:

<!--
```text
0: li r0, 10   # This is decimal 10.
1: li r1, 0
2: li r2, 0
3: li r3, 1
4: add r1, r1, r3
5: add r2, r2, r1
6: bner0 r1, 4
7: bner0 r3, 7
```
-->
```text
0: li r0, 10   # Это десятичное 10.
1: li r1, 0
2: li r2, 0
3: li r3, 1
4: add r1, r1, r3
5: add r2, r2, r1
6: bner0 r1, 4
7: bner0 r3, 7
```

<!--
At first glance, you may find it difficult to understand how the above instruction sequence implements the summation of a sequence. Let's imagine ourselves as a processor and understand the process by executing each instruction one by one. To understand the process of instruction execution, we also need to record the changes in the registers. We use the format `(PC, r0, r1, r2, r3)` to record the values of the registers, which also reflects the state of the processor. For example, `(7, 2, 3, 1, 8)` indicates that the next instruction to be executed is numbered `7`, and the current values of the four GPRs are `2`, `3`, `1`, and `8`. <!--

-->

### State Machine Model of C Programs
-->
### Модель автомата состояний программ на C
<!--
Perhaps you have already sensed that the concepts of variables and statements in C language are somewhat similar to the concepts of GPR and instructions mentioned above in ISA. In fact, from the perspective of computer systems, they are indeed closely related. Similar to ISA, we can also understand C programs from the perspective of state machines:
-->
Возможно, вы уже почувствовали, что понятия переменных и операторов в языке C в чём-то похожи на упомянутые выше понятия GPR и инструкций в ISA. На самом деле, с точки зрения компьютерных систем, они действительно тесно связаны. Подобно ISA, программы на C тоже можно понимать с точки зрения автомата состояний:

<!--
* State set. In C programs, the most direct state is variables, as they are objects that store information. In addition, as mentioned earlier: `the statements within curly braces are executed in order by default`. Naturally, during the execution of a C program, there also needs to be an implicit variable to indicate which statement is currently being executed, this implicit variable is the 'program counter' (PC) in the C language, and it should also be part of the state. Therefore, in a C program, a state is a set of specific variables and the PC, and the set of all states $S$ is the combination of all possible values of variables and the PC, i.e., $S = \{(PC, V)\}$, where $V$ represents the values of all variables in the program.

* Event set. In C programs, execution statements change the state, so execution statements are the events for this state machine.

* State transition rules. According to the behaviour of C programs, state transition rules are used to describe 'the next state after executing a certain statement in a certain state', i.e. the semantics of the statement. It specifies how the state should change after executing a certain statement, so that it transitions from one state to another.

* Initial state. The state before any statements are executed, i.e., $S_0 = (the position of the first statement in the main function, V_0)$.
-->
* Множество состояний. В программах на C наиболее непосредственное состояние — это переменные, поскольку они являются объектами, хранящими информацию. Кроме того, как упоминалось ранее: «операторы внутри фигурных скобок по умолчанию выполняются по порядку». Естественно, во время выполнения программы на C также нужна неявная переменная, указывающая, какой оператор выполняется в данный момент, — эта неявная переменная и есть «счётчик команд» (PC) в языке C, и она тоже должна входить в состояние. Поэтому в программе на C состояние — это набор конкретных значений переменных и PC, а множество всех состояний $S$ — это комбинация всех возможных значений переменных и PC, то есть $S = \{(PC, V)\}$, где $V$ обозначает значения всех переменных программы.

* Множество событий. В программах на C выполнение операторов меняет состояние, поэтому выполнение операторов — это событие для данного автомата состояний.

* Правила перехода состояний. Согласно поведению программ на C, правила перехода состояний описывают «следующее состояние после выполнения некоторого оператора в некотором состоянии», то есть семантику оператора. Они задают, как должно измениться состояние после выполнения определённого оператора, чтобы произошёл переход из одного состояния в другое.

* Начальное состояние. Состояние до выполнения каких-либо операторов, то есть $S_0 = (позиция первого оператора в функции main, V_0)$.

The following is the execution process of the above C program:

Изложив приведённую выше модель автомата состояний, мы можем понять процесс выполнения программы на C с точки зрения автомата состояний. Согласно соглашениям языка C, начальное состояние — `(2, ?, ?, ?)`, где PC равно `2`, что означает, что выполнение начинается со строки 2, то есть с первого оператора функции `main`, а `?` означает, что переменная ещё не определена или не инициализирована. Ниже показан процесс выполнения приведённой выше программы на C:

### Implementing a Sequence Sum in C

### Реализация суммирования последовательности на C

We can also use C language to calculate `1+2+...+10`. Consider the following C program:

Если истинно, тело цикла повторяется; иначе цикл завершается, и выполняются последующие операторы.

1. Имена переменных могут более наглядно отражать их назначение, тогда как в языке ассемблера назначение GPR можно определить только по контексту.
2. Выражения циклов более понятны и позволяют напрямую различать условие цикла и тело цикла, тогда как в языке ассемблера условие цикла и тело цикла — это одни и те же инструкции, и их приходится различать по контексту.

## Модель автомата состояний цифровых схем
<!--
In the previous paragraph, we mentioned 'implementing this model machine in our minds through digital circuits'. This means that digital circuits can also establish some kind of connection with ISA. So, can we also understand the behaviour of digital circuits from the perspective of state machines?
-->
В предыдущем абзаце мы упомянули «реализацию этой существующей в сознании модельной машины с помощью цифровых схем». Это означает, что цифровые схемы тоже могут установить некую связь с ISA. Так можем ли мы также понимать поведение цифровых схем с точки зрения автомата состояний?

<!--
The answer is yes! Based on the knowledge of digital circuits in the previous section, we can easily summarise the state machine model of digital circuits:
-->
Ответ — да! Опираясь на знания о цифровых схемах из предыдущего раздела, можно легко сформулировать модель автомата состояний цифровых схем:

<!--
* State set. In digital circuits, only sequential logic circuits can store information. Therefore, a state is the specific information stored by a sequential logic element, and the set of all states $S$ is the combination of all information that can be stored by sequential logic elements.

* Event set. Since sequential logic elements represent the states of digital circuits, and the internal state of sequential logic elements can be changed through their input terminals (e.g., data can be written into a D flip-flop through its input terminal), we can view digital circuits as the following model:
-->
* Множество состояний. В цифровых схемах только последовательностные логические схемы способны хранить информацию. Поэтому состояние — это конкретная информация, хранимая последовательностным логическим элементом, а множество всех состояний $S$ — это комбинация всей информации, которую способны хранить последовательностные логические элементы.

* Множество событий. Поскольку последовательностные логические элементы представляют состояния цифровой схемы, а внутреннее состояние последовательностных логических элементов можно изменить через их входные выводы (например, данные можно записать в D-триггер через его входной вывод), цифровую схему можно рассматривать в виде следующей модели:

```text
    +------------------+
+-->| Sequential Logic |----+
|   +------------------+    |
| next state                | current state
|                           |
|  +---------------------+  |
+--| Combinational Logic |<-+
   +---------------------+
```

```text
    +-----------------------------+
+-->| Последовательностная логика |----+
|   +-----------------------------+    |
| следующее                            | текущее
| состояние                            | состояние
|                                      |
|   +-----------------------+          |
+---| Комбинационная логика |<---------+
    +-----------------------+
```

<!--
In other words, it is the signal output by the combinational logic circuit that causes the state of the sequential logic element to change. Therefore, the combinational logic circuit is the event for this state machine.
-->
Иными словами, именно сигнал, выдаваемый комбинационной логической схемой, вызывает изменение состояния последовательностного логического элемента. Поэтому комбинационная логическая схема — это событие для данного автомата состояний.

<!--
* State transition rules. How the state of a sequential logic element should change is determined by the specific logic of the combinational logic circuit.
-->
* Правила перехода состояний. То, как должно измениться состояние последовательностного логического элемента, определяется конкретной логикой комбинационной логической схемы.

<!--
* Initial state. This refers to the state of the sequential logic element when the circuit is reset.
-->
* Начальное состояние. Это состояние последовательностного логического элемента в момент сброса схемы.

## Executing C Programs on a Computer

## Выполнение программ на C на компьютере
<!--
We understand the execution process of a C program from the perspective of a state machine, which essentially means executing the C program in our minds. Мы понимаем процесс выполнения программы на C с точки зрения автомата состояний, что по сути означает выполнение программы на C в нашем сознании. <!--
### Compilation = Translating C Code into a Sequence of Instructions
-->
### Компиляция = перевод кода C в последовательность инструкций
<!--
This process has a special name in computer systems: 'compilation'.In principle, compilation can be done manually, but modern programs are very large, and manual compilation is very tedious. Therefore, compilation is usually performed by a special type of program called a 'compiler'.
-->
У этого процесса в компьютерных системах есть специальное название: «компиляция». В принципе, компиляцию можно выполнить вручную, но современные программы очень велики, и ручная компиляция очень утомительна. Поэтому компиляцию обычно выполняет специальный тип программы, называемый «компилятором».

<!--
Since executing C programs and executing instruction sequences can both be understood from a state machine perspective, we can also try to understand what tasks a compiler needs to perform. Let's first list the contents of the two state machines (we will not concern ourselves with the initial state here):
-->
Поскольку и выполнение программ на C, и выполнение последовательностей инструкций можно понимать с точки зрения автомата состояний, мы также можем попробовать понять, какие задачи должен решать компилятор. Сначала перечислим содержимое двух автоматов состояний (начальное состояние здесь рассматривать не будем):

<!--
| | **C program** | **ISA** |
|---|---|---|
| State | $\{PC, V\}$ | $\{PC, R, M\}$ |
| Event | Executed statement | Executed instruction |
| State transition rule | Semantics of statement | Semantics of instruction |
-->
| | **Программа на C** | **ISA** |
|---|---|---|
| Состояние | $\{PC, V\}$ | $\{PC, R, M\}$ |
| Событие | Выполненный оператор | Выполненная инструкция |
| Правило перехода состояний | Семантика оператора | Семантика инструкции |

<!--
Therefore, the compiler's job is to translate the state machine of the C program into the state machine of the ISA, or in other words, construct
-->
Поэтому задача компилятора — перевести автомат состояний программы на C в автомат состояний ISA, иными словами, построить

$$
\begin{aligned}
compile_S &: \{PC, V\} \rightarrow \{PC, R, M\} \\
compile_E &: \{statement\} \rightarrow \{instructionsequence\}
\end{aligned}
$$

<!--
make
-->
так, чтобы

$$compile_S(next(S_{C,k}, statement)) = next(compile_S(S_{C,k}), compile_E(statement))$$

<!--
thus,
-->
тогда,

$$
\begin{aligned}
& compile_S(S_{C,k+1}) \\
= & \ compile_S(next(S_{C,k}, statement)) \\
= & \ next(compile_S(S_{C,k}), compile_E(statement)) \\
= & \ next(S_{ISA,k}, instructionsequence) \\
= & \ S_{ISA,k+1}
\end{aligned}
$$

<!--
In this context, $S_{C,k}$ denotes the $k$ th state of the C language state machine, and $S_{ISA,k}$ denotes the $k$ th state of the ISA state machine. In natural language, this means: The state of a C program after executing a statement is semantically equivalent to the state of the ISA after executing the instruction sequence obtained from compilation.
-->
Здесь $S_{C,k}$ обозначает $k$-е состояние автомата состояний языка C, а $S_{ISA,k}$ обозначает $k$-е состояние автомата состояний ISA. На естественном языке это означает: состояние программы на C после выполнения оператора семантически эквивалентно состоянию ISA после выполнения последовательности инструкций, полученной в результате компиляции.

<!--
Specifically, after comparing the two state machines, we can see that the compiler needs to perform the following tasks:
-->
А именно, сравнив два автомата состояний, можно увидеть, что компилятору нужно выполнить следующие задачи:

<!--
* Translate the state of the C program into the state of the ISA, i.e.
  * Map the PC of the C program to the PC of the ISA
  * Map the variables of the C program to the GPR or memory of the ISA
* Translate the state transition rules of the C program into the state transition rules of the ISA, i.e., translate statements into instruction sequences.
-->
* Перевести состояние программы на C в состояние ISA, то есть
  * Отобразить PC программы на C на PC ISA
  * Отобразить переменные программы на C на GPR или память ISA
* Перевести правила перехода состояний программы на C в правила перехода состояний ISA, то есть перевести операторы в последовательности инструкций.

### CPU design = Designing Digital Circuits Based on ISA
-->
### Проектирование CPU = проектирование цифровых схем на основе ISA
<!--
Similarly, since ISAs and digital circuits can both be understood from a state machine perspective, we can also try to understand how CPU design should be carried out. Let's first list the contents of the two state machines (we will not concern ourselves with the initial state here):

Аналогично, поскольку и ISA, и цифровые схемы можно понимать с точки зрения автомата состояний, мы также можем попробовать понять, как должно вестись проектирование CPU. Сначала перечислим содержимое двух автоматов состояний (начальное состояние здесь рассматривать не будем):

-->
Поэтому задача проектирования CPU — реализовать автомат состояний ISA с помощью автомата состояний цифровой схемы, иными словами, построить

$$

<!--

так, чтобы

$$CPUdesign_S(next(S_{ISA,k}, Instruction)) = next(CPUdesign_S(S_{ISA,k}), CPUdesign_E(Instruction))$$

<!--
thus,

тогда,

$$
\begin{aligned}
& CPUdesign_S(S_{ISA,k+1}) \\

\end{aligned}
$$

<!--
Among them, $S_{CPU,k}$ represents the $k$ th state of the CPU circuit state machine. Described in natural language, it is: the state after the ISA executes an instruction is semantically equivalent to the next state of the designed CPU under the control of combinational logic circuits.
-->
Здесь $S_{CPU,k}$ обозначает $k$-е состояние автомата состояний схемы CPU. На естественном языке это означает: состояние после выполнения ISA инструкции семантически эквивалентно следующему состоянию спроектированного CPU под управлением комбинационных логических схем.

<!--
* Implement the ISA states using digital circuit states, i.e., implement the PC, GPR, and memory using sequential logic circuits.
* Implement the ISA state transition rules using digital circuit state transition rules, i.e., implement the functions of instructions using combinational logic circuits.
-->
* Реализовать состояния ISA с помощью состояний цифровой схемы, то есть реализовать PC, GPR и память с помощью последовательностных логических схем.
* Реализовать правила перехода состояний ISA с помощью правил перехода состояний цифровой схемы, то есть реализовать функции инструкций с помощью комбинационных логических схем.

## The Relationship between Programs, ISAs, and CPUs

<!--
At this point, we can briefly review the relationship between the program, ISA, and CPU:

 * На этом этапе три автомата состояний оказываются взаимосвязаны: $S_C \sim S_{ISA} \sim S_{CPU}$
