## sCPU с единственной инструкцией

<!--
Let's first review the specific process of executing a li instruction using the ISA state machine model.In fact, regardless of the instruction being executed, the steps are similar.There is a concept called the ‘instruction cycle’ that specifically describes these steps:
-->
Сначала вспомним конкретный процесс выполнения инструкции li с помощью модели автомата состояний ISA. На самом деле, какая бы инструкция ни выполнялась, шаги схожи. Есть понятие «цикл инструкции», которое как раз описывает эти шаги:

<!--
1. Fetch: Based on the current PC, locate an instruction in memory.
2. Decode: Determine the specific type of instruction and its operands 
 * For example, with the `li` instruction, the operand requires checking the immediate value and determining which destination register to write to
3. Execute: Process the operands and update the specified destination register if necessary
4. Update PC: Set the PC to point to the next instruction
-->
1. Выборка (Fetch): по текущему PC найти инструкцию в памяти.
2. Декодирование (Decode): определить конкретный тип инструкции и её операнды
 * Например, для инструкции `li` операнд требует проверить непосредственное значение и определить, в какой регистр-приёмник записывать
3. Выполнение (Execute): обработать операнды и при необходимости обновить указанный регистр-приёмник
4. Обновление PC (Update PC): установить PC так, чтобы он указывал на следующую инструкцию

<!--
Therefore, our goal is to implement each of these steps using digital circuits.
-->
Поэтому наша цель — реализовать каждый из этих шагов с помощью цифровых схем.

### Выборка

<!--
First, you need a PC register. You have already implemented registers using digital circuits, so the PC register is not difficult to implement. Then, you need to find an instruction in the memory based on the PC, so you also need to implement the memory.
-->
Сначала нужен регистр PC. Вы уже реализовывали регистры с помощью цифровых схем, поэтому реализовать регистр PC несложно. Затем нужно найти инструкцию в памяти по значению PC, поэтому также нужно реализовать память.

<!--
Both memory and registers can store information, but memory also supports addressing. That is, the contents of memory are arranged in order; given an address, memory can read out the content corresponding to that address. We can regard memory as a matrix composed of bits, where each row of the matrix is called a memory word, the address is the row number, and the number of rows is called the memory depth. Typically, a memory word contains multiple bits of data, and its bit-width is called the memory width. Memory specifications are usually expressed as `depth x width`. For example, a `2x3` memory is arranged as follows, where $b_{(x,y)}$ represents the bit stored in the $x$ row and $y$ column
-->
И память, и регистры способны хранить информацию, но память также поддерживает адресацию. То есть содержимое памяти расположено по порядку; по заданному адресу память может считать содержимое, соответствующее этому адресу. Память можно рассматривать как матрицу, составленную из битов, где каждая строка матрицы называется словом памяти, адрес — это номер строки, а количество строк называется глубиной памяти. Обычно слово памяти содержит несколько битов данных, и его разрядность называется разрядностью памяти. Характеристики памяти обычно выражаются как `глубина x разрядность`. Например, память `2x3` устроена следующим образом, где $b_{(x,y)}$ обозначает бит, хранящийся в строке $x$ и столбце $y$

<!--
| Address | Memory Word |
| :---: | :---: |
| 0 | $b_{(0,2)}b_{(0,1)}b_{(0,0)}$ |
| 1 | $b_{(1,2)}b_{(1,1)}b_{(1,0)}$ |
-->
| Адрес | Слово памяти |
| :---: | :---: |
| 0 | $b_{(0,2)}b_{(0,1)}b_{(0,0)}$ |
| 1 | $b_{(1,2)}b_{(1,1)}b_{(1,0)}$ |

<!--
Functionally, memory can be categorized into Read-Only Memory (ROM) and Random Access Memory (RAM). The former does not support write operations, while the latter does. For sISA, since none of its three instructions access memory (only instruction fetch requires reading instructions from memory), ROM can be implemented here.
-->
По функциональности память можно разделить на ROM (постоянную память, Read-Only Memory) и RAM (оперативную память, Random Access Memory). Первая не поддерживает операции записи, а вторая поддерживает. Для sISA, поскольку ни одна из трёх её инструкций не обращается к памяти (только выборка инструкций требует чтения инструкций из памяти), здесь можно реализовать ROM.

<!--
The structure of a `2x3` ROM is shown in the figure below. The decoder at the upper left is called the 'address decoder', and the wires connected to the address decoder outputs are called 'word lines'. Each word line performs an AND operation with the memory cells in the corresponding memory word, then the results of the AND gates in the same column undergo an OR operation. The wires connected to the OR gate outputs are called 'bit lines'.
![bit lines](https://ysyx.oscc.cc/slides/2306/resources/img/tikz-images/3e4761728feb60e13a5683df85b3960461e008fb.png)
-->
Структура ROM `2x3` показана на рисунке ниже. Дешифратор в левом верхнем углу называется «дешифратором адреса», а провода, подключённые к выходам дешифратора адреса, называются «линиями слова». Каждая линия слова выполняет операцию AND с ячейками памяти в соответствующем слове памяти, а затем результаты элементов AND в одном столбце проходят операцию OR. Провода, подключённые к выходам элементов OR, называются «битовыми линиями».
![битовые линии](https://ysyx.oscc.cc/slides/2306/resources/img/tikz-images/3e4761728feb60e13a5683df85b3960461e008fb.png)

<!--
Given an address `addr`, the corresponding memory word can be read from the ROM through the following process: The address decoder converts the input address into a one-hot code. Since only one bit is active in the one-hot encoding, among all word lines, only the word line corresponding to `addr` becomes active. This enables the stored information in that row to pass through the AND gates. Information in other rows is filtered to `0` by the AND gates due to their inactive word lines. Each bit of the selected memory word is then transmitted through the OR gates to the bit lines, outputting the data externally from the memory.
-->
По заданному адресу `addr` соответствующее слово памяти можно считать из ROM следующим образом: дешифратор адреса преобразует входной адрес в унитарный код. Поскольку в унитарном коде активен только один бит, среди всех линий слова активной становится только линия слова, соответствующая `addr`. Это позволяет хранимой в этой строке информации пройти через элементы AND. Информация в остальных строках отфильтровывается элементами AND до `0` из-за неактивных линий слова. Затем каждый бит выбранного слова памяти передаётся через элементы OR на битовые линии, выводя данные из памяти наружу.

<!--
Functionally, the address decoder, AND gates, and OR gates in the diagram collectively form a 3-bit 2-to-1 multiplexer. Consequently, reading from ROM can be viewed as selecting one memory word from multiple stored words, where the address `addr` acts as the multiplexer's selection input, and all memory words serve as its data inputs. Notably, information stored in ROM is directly encoded using voltage levels (high/low), making the ROM functionally equivalent to a multiplexer with constant data inputs.
-->
По функциональности дешифратор адреса, элементы AND и элементы OR на рисунке в совокупности образуют 3-битный мультиплексор «2 в 1». Следовательно, чтение из ROM можно рассматривать как выбор одного слова памяти из нескольких хранимых слов, где адрес `addr` служит входом выбора мультиплексора, а все слова памяти — его входами данных. Примечательно, что информация, хранящаяся в ROM, напрямую закодирована уровнями напряжения (высокий/низкий), что делает ROM функционально эквивалентным мультиплексору с постоянными входами данных.

### Декодирование

<!--
The purpose of decoding is to identify the function of an instruction from its encoding. When executing instructions on the ISA state machine, we can identify their functions directly from their assembly representations (e.g., `li r0, 10`), or determine their functions from their binary representations (e.g., `10001010`) by consulting the instruction specifications. In essence, both approaches perform instruction decoding manually. Now we need to implement this process using hardware circuits. Since instructions are stored in binary form in the circuit, decoding must also be performed at the binary level.
-->
Цель декодирования — определить функцию инструкции по её кодировке. При выполнении инструкций на автомате состояний ISA мы можем определить их функцию напрямую по представлению на ассемблере (например, `li r0, 10`) или определить их функцию по двоичному представлению (например, `10001010`), сверяясь со спецификацией инструкций. По сути, оба подхода выполняют декодирование инструкции вручную. Теперь нам нужно реализовать этот процесс с помощью аппаратных схем. Поскольку в схеме инструкции хранятся в двоичном виде, декодирование тоже нужно выполнять на уровне двоичных разрядов.

<!--
Instruction decoding can be further divided into opcode decoding and operand decoding. Opcode decoding identifies the function of an instruction based on its opcode, while operand decoding extracts the corresponding operands from the instruction encoding.For opcode decoding, since only the `li` instruction needs to be implemented at this stage, we can assume that every fetched instruction is an `li` instruction. For operand decoding, we only need to extract the `rd` and `imm` fields from the `li` instruction. From a circuit perspective, these are simply bit-field extraction operations and are straightforward to implement.
-->
Декодирование инструкции можно дополнительно разделить на декодирование кода операции и декодирование операндов. Декодирование кода операции определяет функцию инструкции по её коду операции, а декодирование операндов извлекает соответствующие операнды из кодировки инструкции. Для декодирования кода операции, поскольку на этом этапе нужно реализовать только инструкцию `li`, можно считать, что каждая выбранная инструкция — это инструкция `li`. Для декодирования операндов нужно лишь извлечь поля `rd` и `imm` из инструкции `li`. С точки зрения схемы это просто операции извлечения битовых полей, и реализовать их несложно.

### Выполнение

<!--
The `li` instruction loads the immediate value `imm` into the `rd` register. Consequently, we must address the implementation of the ISA's General-Purpose Registers.
-->
Инструкция `li` загружает непосредственное значение `imm` в регистр `rd`. Следовательно, нам нужно заняться реализацией регистров общего назначения ISA.

<!--
Typically, a GPR set contains multiple registers, with each access targeting only specific registers. Thus, the GPR must support addressing. This reveals that the GPR circuit is fundamentally a memory device. However, since GPRs serve as destination registers for instruction writes, they require writable memory functionality—making them RAM.
-->
Обычно набор GPR содержит несколько регистров, и при каждом обращении затрагиваются только конкретные регистры. Таким образом, GPR должны поддерживать адресацию. Отсюда следует, что схема GPR по сути является запоминающим устройством. Однако, поскольку GPR служат регистрами-приёмниками для записи инструкций, им требуется функциональность памяти с возможностью записи — то есть они являются RAM.

<!--
Consider a `2×3` RAM whose read operation structure is shown in the figure below. Observe that except for the storage cells being implemented with D flip-flops, the remaining structure mirrors that of a ROM. Consequently, the read operation workflow of RAM can reference the description in the aforementioned ROM section.
![2×3RAM](https://ysyx.oscc.cc/slides/2306/resources/img/tikz-images/dd11d5756391fdd050b2d709d8c44398c90b30e3.png)
-->
Рассмотрим RAM `2×3`, структура операции чтения которой показана на рисунке ниже. Обратите внимание, что за исключением ячеек хранения, реализованных на D-триггерах, остальная структура повторяет структуру ROM. Следовательно, процесс операции чтения RAM можно понимать так же, как описано в разделе про ROM выше.
![RAM 2×3](https://ysyx.oscc.cc/slides/2306/resources/img/tikz-images/dd11d5756391fdd050b2d709d8c44398c90b30e3.png)

<!--

-->
Для операций записи в RAM задействованная структура показана на рисунке ниже. Для выполнения записи требуется не только адрес, но и данные для записи `D`. Поскольку RAM не всегда нуждается в записи (например, при выполнении инструкции `bner0` запись в GPR не нужна), необходим сигнал разрешения записи `EN`, указывающий, должна ли происходить запись.
![запись в RAM](https://ysyx.oscc.cc/slides/2306/resources/img/tikz-images/324171040aac2f903bef57d8bb9b981960a51d7f.png)

<!--
Given an address `addr` and write data `D`, when write enable `EN` is active, data `D` can be written to the corresponding memory word in RAM. The process operates as follows: Write data `D` connects each bit to the `D`-inputs of all memory cells in corresponding bit positions via bit lines. The enable signal `EN` filters the one-hot code output from the address decoder through an AND gate and connects to the word line. Consequently when `EN` is active, only the word line for `addr` asserts while others remain deasserted. Each row's word line connects to the enable (`EN`) input of its memory cells, causing the selected memory word to latch write data `D` at the next clock edge, completing the write operation.
-->
При заданном адресе `addr` и данных для записи `D`, когда разрешение записи `EN` активно, данные `D` можно записать в соответствующее слово памяти RAM. Процесс происходит так: данные для записи `D` подключают каждый бит ко входам `D` всех ячеек памяти в соответствующих битовых позициях через битовые линии. Сигнал разрешения `EN` фильтрует унитарный код, выдаваемый дешифратором адреса, через элемент AND и подключается к линии слова. Следовательно, когда `EN` активен, активной становится только линия слова для `addr`, остальные остаются неактивными. Линия слова каждой строки подключена ко входу разрешения (`EN`) её ячеек памяти, из-за чего выбранное слово памяти защёлкивает данные для записи `D` на следующем фронте такта, завершая операцию записи.

Соответственно, некоторые RAM могут одновременно обращаться к нескольким словам памяти по нескольким адресам — их называют «многопортовыми RAM». Очевидно, что увеличение числа «портов» в RAM требует добавления дополнительной схемной логики, чтобы схемная логика нескольких портов могла работать одновременно.

## Реализация полного sCPU
<!--
Next, consider how to implement the `add` instruction. Since for all instructions, the two steps of instruction fetch and PC update behave the same way, we can directly reuse the previously implemented instruction fetch logic.
-->
Далее рассмотрим, как реализовать инструкцию `add`. Поскольку для всех инструкций два шага — выборка инструкции и обновление PC — ведут себя одинаково, мы можем напрямую повторно использовать ранее реализованную логику выборки инструкций.

<!--
For decoding, since the behavior of the `add` instruction differs from that of the `li` instruction, it is necessary to identify which instruction is currently fetched. To achieve this, we need to check the `opcode` field of the instruction: if it is `00`, it is an `add` instruction; if it is `10`, it is an `li` instruction. The most suitable circuit for identifying the value of an input is a decoder! Since the `opcode` is only 2 bits, we can use a 2-4 decoder. The one-hot code it outputs can indicate the type of the current instruction, and such a decoder is called an instruction decoder. This set of one-hot codes usually serves as control signals to control how part of the circuit works, thereby supporting the functions of different instructions.
-->
Для декодирования, поскольку поведение инструкции `add` отличается от поведения инструкции `li`, нужно определить, какая инструкция выбрана в данный момент. Для этого нужно проверить поле `opcode` инструкции: если оно равно `00`, это инструкция `add`; если `10` — это инструкция `li`. Наиболее подходящая схема для определения значения входа — дешифратор! Поскольку `opcode` занимает всего 2 бита, можно использовать дешифратор «2 в 4». Выдаваемый им унитарный код может указывать тип текущей инструкции, и такой дешифратор называется дешифратором инструкций. Этот набор унитарных кодов обычно служит управляющими сигналами, управляющими работой части схемы, тем самым поддерживая функции различных инструкций.

<!--
After considering the operation code, we also need to take the operands into account. Compared with the `li` instruction, the `add` instruction not only needs to write to rd, but also needs to read `rs1` and `rs2` as source operands, requiring simultaneous access to GPR through two read ports and one write port. Therefore, we also need to add two read ports to GPR. After adding, the GPR module should contain at least the following port signals:
-->
Рассмотрев код операции, нужно также учесть операнды. По сравнению с инструкцией `li`, инструкции `add` нужно не только записывать в rd, но и читать `rs1` и `rs2` как исходные операнды, что требует одновременного обращения к GPR через два порта чтения и один порт записи. Поэтому нам также нужно добавить к GPR два порта чтения. После добавления модуль GPR должен содержать как минимум следующие портовые сигналы:

<!--
* 1st read port: `raddr1` (read address), `rdata1` (read data)
* 2nd read port: `raddr2`, `rdata2`
* Write port: `waddr` (write address), `wdata` (write data), `wen` (write enable), `clk` (clock)
-->
* 1-й порт чтения: `raddr1` (адрес чтения), `rdata1` (данные чтения)
* 2-й порт чтения: `raddr2`, `rdata2`
* Порт записи: `waddr` (адрес записи), `wdata` (данные записи), `wen` (разрешение записи), `clk` (тактовый сигнал)

<!--
After reading out the source operands, the behavior of the `add` instruction is to add the two numbers and then write the addition result to the `rd` register. The former can be implemented via an adder, but when the latter writes to GPR, the `wdata` port of GPR is already occupied by the result of the `li` instruction. Considering the uniqueness of instruction opcode encoding, an instruction cannot be both an `li` instruction and an `add` instruction. Therefore, the data to be written to GPR can be selected based on the instruction type: if the current instruction is an add instruction, the result of the adder is selected; otherwise, the immediate value of the `li` instruction is selected. Such a selection function can be implemented through a multiplexer: take the two data sources to be written to GPR as the data terminals of the multiplexer, and then connect the appropriate signal from the one-hot code during decoding to the select terminal of the multiplexer. This allows the multiplexer to select the correct data according to the instruction type, thereby realizing the aforementioned function.
-->
После считывания исходных операндов поведение инструкции `add` заключается в сложении двух чисел и последующей записи результата сложения в регистр `rd`. Первое можно реализовать с помощью сумматора, но когда второе записывается в GPR, порт `wdata` GPR уже занят результатом инструкции `li`. Учитывая уникальность кодировки кода операции инструкции, инструкция не может одновременно быть и инструкцией `li`, и инструкцией `add`. Поэтому данные, записываемые в GPR, можно выбирать в зависимости от типа инструкции: если текущая инструкция — add, выбирается результат сумматора; иначе выбирается непосредственное значение инструкции `li`. Такую функцию выбора можно реализовать с помощью мультиплексора: возьмите два источника данных, записываемых в GPR, как входы данных мультиплексора, а затем подключите соответствующий сигнал из унитарного кода, полученного при декодировании, ко входу выбора мультиплексора. Это позволяет мультиплексору выбирать нужные данные в зависимости от типа инструкции, тем самым реализуя описанную выше функцию.

Поскольку положение поля `rs2` в инструкции `bner0` совпадает с положением в инструкции `add`, можно повторно использовать логику чтения регистра `rs2` из инструкции `add`. <!--
When discussing how to add instructions earlier, we first analyzed the intended behavior of each instruction, then sequentially added the required components along the direction of data flow based on the instruction's behavior. The paths through which data flows in the CPU, along with the related components on these paths, are called the CPU's data path. Обсуждая ранее, как добавлять инструкции, мы сначала анализировали предполагаемое поведение каждой инструкции, а затем последовательно добавляли необходимые компоненты вдоль направления потока данных, исходя из поведения инструкции. <!--

In fact, designing the data path and control signals are precisely the two most critical steps in CPU design.

Когда между несколькими инструкциями возникают конфликты тракта данных, обычно требуется вводить дополнительные схемы, чтобы управлять потоком данных, гарантируя, что каждая инструкция может выполнять операции в соответствии со спецификацией ISA. Эти дополнительные схемы относятся к управляющей логике внутри CPU, а сигналы, определяющие поведение управляющей логики, называются управляющими сигналами. На самом деле, проектирование тракта данных и управляющих сигналов — это именно те два самых важных шага при проектировании CPU.
